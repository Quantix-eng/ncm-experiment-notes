# Reproducing the work

[Experiment overview](../README.md#all-20-experiments-at-a-glance) · [Connections](../experiments/README.md) · [Scope and provenance](scope.md) · [Related work](related-work.md)

There are three different things you can do with this repository. Checking a saved calculation is quick. Loading a checkpoint takes more setup. Repeating every historical campaign still requires some work on paths, dependencies and inputs. We keep those distinctions explicit.

## Small checks, without a model

From the repository root, with Python 3.10 or later:

```sh
python3 scripts/check_pooling_identity.py
python3 scripts/recompute_ioi.py
python3 scripts/verify_release.py
```

The pooling check constructs additive embeddings and Sudoku permutations. It illustrates the mathematical identity; it does not inspect a trained tokenizer. The IOI check recomputes contrasts from saved observations for three heads. It does not rerun GPT-2 or estimate new confidence intervals. The release check compares copied files with their recorded hashes and checks the curated links and new scripts' syntax.

## A small checkpoint check

The following is a new inference smoke test for the hard Sudoku checkpoint. It compares native predictions with predictions whose level-5 head is forced to identifier 11 on the first 16 puzzles. It runs that head before replacing its output, so it measures neither a computational saving nor a speedup.

Use a separate environment. Python 3.11 or 3.12 is a reasonable starting point for dependency availability:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-smoke.txt
.venv/bin/python scripts/download_sudoku.py
.venv/bin/python scripts/check_level5.py --n 16 --output runs/level5-check.json
```

The downloader reads the archived `assets.lock.json`, downloads the hard checkpoint and data at the recorded Hugging Face revisions, and checks their sizes and hashes. Downloads go to `runs/sudoku/`, outside the historical copies. Existing files with different contents cause an error. The upstream dataset includes a pickle file: only load the pinned, verified input you intended to use.

This dependency file is a proposed installation recipe for the small check, not a lockfile for all twenty campaigns. A fresh installation and network download have not been validated as part of packaging. The [local smoke-test record](../provenance/smoke-level5.json) uses the existing environment with PyTorch 2.8.0 on CPU, float32 and one thread. All four compared outputs match on 16 puzzles. This checks one small case, not the historical held-out study.

## The historical campaigns

Choose a study in the [README overview](../README.md#all-20-experiments-at-a-glance), then open its individual page. Each page links to the original scripts and saved records. The scripts retain their original contents, including local paths and output conventions. Do not run a campaign inside `historical/` if you want to preserve the exported snapshot.

For a working copy:

```sh
mkdir -p runs
cp -R historical/Experience_NCM runs/replay
```

Then read that campaign's original protocol before running its entry point. Restore its input files, install its recorded dependencies, and adjust machine-specific paths in the working copy. Some runners write results or enforce protocol hashes; changing paths may require a new, explicitly labelled protocol record. Do not present such a rerun as the unchanged original freeze.

NCM, GPT-2, Pythia and InterpBench campaigns have different requirements. There is deliberately no single dependency file claiming to cover them all. Original environment records and model references are included alongside the relevant campaigns. Installed environments, model weights and numerical arrays are excluded from this repository; the [export inventory](../provenance/historical-manifest.json) lists omissions and available hashes. Some arrays must be regenerated by their producing scripts before later analysis scripts will run.

The saved JSON results make the reported observations inspectable. They do not make every experiment portable by themselves. Remaining work includes testing fresh installations, documenting per-campaign input restoration and running the full workflows on a second machine. No independent replication is claimed.

## About the packaging checks

`provenance/packaging-checks.json` records checks made when preparing this copy. Where the original directory is available, `python3 scripts/verify_release.py --check-originals` also checks that the exported source files still match it. This verifies the copied files, not the scientific interpretation of their results.
