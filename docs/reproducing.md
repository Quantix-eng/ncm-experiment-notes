# Setup and execution

[Overview](../README.md#all-20-experiments-at-a-glance) · [Shared dependencies](../common/README.md) · [Scope](scope.md)

## Start in an experiment folder

Every experiment provides the same entry point:

```sh
python3 run.py check
python3 run.py stages
python3 run.py run <stage> --plan
python3 run.py run <stage> --name trial-01 --assets /absolute/path/to/assets
```

`check` executes that study’s `src/check_recorded.py`. These checks recompute available counts, ratios or contrasts from saved data and validate selected invariants. They do not constitute fresh model inference or independent confirmation. `stages` lists the actual computational sources and fixed arguments; `--plan` shows a stage without executing it.

Install the relevant [dependencies](../common/README.md) before executing a model stage. Use the environment’s Python in place of `python3`. Required inputs are listed in `experiment.json` and the study README. Stage order matters: training precedes fitted probes; development and calibration precede test evaluation. Existing competence, damage and integrity gates are retained.

## Assets and intermediate arrays

`python -m common.download_sudoku` downloads pinned hard Sudoku assets to the root `assets/` directory. Select `--difficulty easy` or `medium` for the other official checkpoints. Other campaigns need GPT-2, Pythia, text tokenizers, InterpBench weights or compiled reference sources. Their recorded input metadata identifies revisions; there is not yet a tested unified downloader for those resources.

Large `.npz` and `.npy` traces are excluded. Some stages need arrays generated by earlier campaigns, especially the initial Sudoku extraction and probe training. Their omission is listed in [source inventory](../provenance/source-inventory.json). The source code is included, but having a local entry point does not eliminate those dependencies.

## Output isolation and compatibility

New files go under the selected experiment’s `runs/<name>/`. The saved `recorded/` snapshots are not overwritten. To try a different configuration or changed source, choose a new run name. The execution workspace restores relative paths expected by the existing scripts; the source itself lives in `src/` and `common/`. `run.json` records inputs and source hashes, and `execution.jsonl` records stage exit status.

Only the target study’s prior outcomes are excluded from a new workspace; earlier campaigns’ saved JSON inputs may still be used as dependencies. Such a run is a computational rerun using prior inputs, not independent evidence. New protocol-document fingerprints describe this relocated execution, not the original research freeze.

## Validation status

The repository-wide check executes all twenty recorded-data programs and checks source mapping, local links and syntax. Its saved report is in [packaging checks](../provenance/packaging-checks.json). Fresh checks also executed the checkpoint and algebra stages in experiment 01, the small sample in experiment 02, the fixed-family analytical rerun in experiment 19, and the untrained structural control in experiment 20. These reuse inputs or test structural identities; they are not new independent studies. Do not read either as a validation of all twenty full workflows.

Full model and training campaigns still need end-to-end validation after relocation, fresh dependency-install tests and restoration of omitted intermediate arrays. A failing or blocked stage is not reported as a reproduced result. The complete earlier archive remains available in Git history at the commit recorded in the source inventory.

## A small model trial

After installing NCM dependencies and downloading the hard Sudoku assets, enter experiment 02 and run `python run.py run sample --name trial-01`. This reads the existing discovery table, tests lookup/certification and requested digit writes on eight official puzzles, and writes a scoped JSON report. It does not recreate the historical fresh corpus, Gaussian controls or latency benchmark.
