# Journal de protocole

- 2026-10-24 : protocole v1 écrit avant résultats. Copies autonomes de ncm_mac, dépôt amont, poids et corpus Sudoku. Sources d'expériences antérieures copiées pour référence ; leurs résultats ne sont pas réutilisés.
- Environnement Python local avec accès en lecture aux paquets système ; installations et caches locaux. CPU FP32, un thread. Toutes les conclusions limitées aux checkpoints Sudoku.
- results/progress.json et logs/ consignent exécution et incidents. Le manifeste final identifie les fichiers utilisés ; code amont brut conservé pour comparaison avec le port CPU.
- Le gel horodaté (results/protocol_frozen.json) et les partitions ont été enregistrés avant consultation de tout résultat agrégé ; l'extraction hard avait commencé pour vérifier l'instrumentation.
- Ajout d'un contrôle d'unicité des 6 000 puzzles officiels par Algorithm X : distinguer fidélité à la référence et solution valide, notamment si plusieurs solutions existent.
- Les cinq contrôles causaux aléatoires sont appariés à la norme effective de perturbation de la direction ciblée, par token et par puzzle. Le sham vérifie la neutralité des hooks.
- Compléments avant analyse des sondes : entropie conditionnelle à la position pour l'audit des codes ; sonde de solution fondée uniquement sur les indices comme contrôle ; sondes de niveau 6 réentraînées indépendamment sur easy et medium (réplications secondaires, faible nombre d'erreurs attendu).
- La copie amont présente un aliasing de idx_to_zhats : les historiques bruts partagent le même accumulateur. Le port CPU copié utilise clone() ; chaque historique est contrôlé contre une accumulation explicite. Comparaison directe avec le dépôt amont intact sur 16 puzzles/checkpoint ajoutée, distincte de la comparaison avec/sans cache.
- Exécution concurrente des extractions hard/easy/medium et des expériences indépendantes, chacune à un thread ; verrou par difficulté pour éviter une double extraction. Cela réduit l'attente mais les durées de campagne ne constituent pas un benchmark d'inférence.
- Incident technique : les calculs d'extraction se terminent et le NPZ est enregistré, mais la sérialisation du résumé échoue sur ListConfig (Hydra). Correction : convertir explicitement les longueurs en liste Python. Les processus déjà lancés conservent l'ancienne fonction ; recover_summaries.py reconstruit leurs JSON depuis les NPZ intacts, recontrôle les entrées et rejoue la parité sur 16 puzzles. Aucun réentraînement ni changement de prédiction. Les durées récupérées sont les derniers points de progression, pas des durées totales.
- Amendement exploratoire post-hoc, après observation des codes : le niveau 5 hard encode et génère uniquement le code VQ 11 sur 2 000 puzzles. constant_level.py teste sur les 128 puzzles test déjà utilisés pour les symétries la suppression de sa contribution résiduelle, avec régénération des niveaux suivants et sham. Ce test distingue variation d'information et utilité d'un décalage commun ; il ne fait pas partie du critère principal.
- Intervalles sans discordance : le bootstrap du taux de réussite devient [0,0] lorsqu'aucun statut succès/échec ne change. Le rapport le signale et complète le test du niveau constant par une borne Wilson sur le taux de changements de statut ; aucun effet nul populationnel ni équivalence n'est déduit d'un intervalle bootstrap dégénéré.
- Audit croisé des corpus après les premières sondes : les trois difficultés partagent 2 000/2 000 familles de solutions (aucun puzzle identique sous les symétries testées). Les réplications de checkpoints sont corrélées, non des réplications indépendantes de familles de grilles. Audit sauvegardé dans audit_overlap.py ; le transfert direct des sondes est limité aux familles du test hard pour exclure celles de train/validation hard. Le critère principal hard et ses partitions restent inchangés.
- Cas rare vérifié séparément : la reconstruction finale medium comporte un token erroné sur une grille ; tokenizer_errors.py rejoue tous les cas non nuls dans le tokenizer amont intact. Les comptes exacts complètent les pourcentages arrondis du rapport.
